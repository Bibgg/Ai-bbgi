# Ai-BBGI Android app

This repository keeps the upstream `llama.cpp` inference engine and adds a native Kotlin Android application.

## First APK

1. Open the repository's **Actions** tab.
2. Select **Ai-BBGI Android APK** and wait for the run triggered by a push to `main` (or use **Run workflow**).
3. Download the `Ai-BBGI-APK-...` artifact. It contains debug and release APKs.
4. Install the debug APK on an Android ARM64 device (Android 8.0/API 26 or newer).

The workflow provisions Java 17, Android SDK 35, NDK 27.2.12479018, CMake 3.22.1 and Gradle 8.9. It generates the Gradle wrapper in CI before building; wrapper scripts and the wrapper JAR are therefore generated by the workflow rather than checked into this repository.

## Use a local GGUF model

1. Install the APK and open **Ai-BBGI**.
2. Open **Settings → Choose .gguf model**.
3. Select a GGUF file using Android's document picker. The app copies it into its private app storage and loads it through the JNI bridge linked to `llama.cpp`.
4. Start chatting. The starter build uses CPU inference, a 2,048-token context and a 384-token generation cap. Use a small quantized model appropriate for the phone's available RAM. Large models can cause Android to terminate the app.

The first version targets `arm64-v8a`. GPU offload, streaming token output, conversation history persistence, multimodal input, model download/management and device-specific tuning are not yet included.

## Push generated code to GitHub

1. Create a fine-grained GitHub Personal Access Token restricted to the target repository with **Contents: Read and write** permission.
2. In **Settings**, enter the token, repository as `owner/repo`, and desired file path.
3. Generate a response containing a fenced code block and press **Push to GitHub**.

The token is stored using AndroidX EncryptedSharedPreferences. Never paste a token into chat or commit it to this repository. Revoke the token in GitHub settings if the phone is lost. The app sends the generated code directly to GitHub's Contents API over HTTPS.

## Important implementation notes

- The native inference bridge is in `app/src/main/cpp/NativeBridge.cpp`; the app entry point is `app/src/main/java/com/bibgg/aibbgi/MainActivity.kt`.
- `CMakeLists.txt` includes the JNI target only for Android builds, leaving non-Android llama.cpp builds unchanged.
- `app/build.gradle` disables optional desktop tools, tests, server and OpenMP for the Android library build.
- The workflow currently uploads APKs as Actions artifacts (30-day retention). Release signing is not configured: the release variant is an unsigned-by-your-own-key build suitable for initial testing, not a Play Store production release.

## Build status

A workflow file is committed, but a successful APK is not claimed until the first GitHub Actions run completes. Review compiler and Gradle logs in Actions; native APIs can change when the upstream llama.cpp revision is updated.
